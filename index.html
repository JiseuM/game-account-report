三条关键结论

  1. 7881 的问题不在字段多少，而在「没有反馈」。营地ID 填完点「获取登陆账号信息」后，遮罩只写「获取账号信息中」，实测 60 秒无结果、无超时、无失败文案、无取消入口；同一类动作，螃蟹在 0.3 秒内就能给出「价格范围在 80-999999」级别的明确红字。
  2. 同一概念三家四套叫法，用户跨平台迁移成本高。「营地标识」在 7881 叫「营地ID」、螃蟹（王者）叫「营地账号」、螃蟹（无畏契约）叫「掌瓦id」、盼之干脆叫「游戏账号」并包进「扫码授权」；「区服」则被写成「运营商 / 操作系统 / 账号类型」三种。
  3. 校验时点分成两派。螃蟹边输边校验、并即时联动费用（79 → 红字，80 → 代售费 ¥50 / 到手 ¥30）；盼之在点击「授权上号」时才校验（空 →「请输入游戏账号」，abc →「请填写正确的QQ账号」）；7881 空值时只把按钮置灰，一句提示都没有。
与前序结论的差异（已修正）：上一轮记录「螃蟹一键发布会先弹协议」，本轮实测为先做字段校验——实名未选时点一键发布，只会在这行内联「请选择」，协议弹层要等字段齐了才出现。另：超自然行动组售价下限本轮实测为「最低≥0」，与早前记录的 31 元不一致，以本轮页面文案为准。

01方法与边界

本页评价 · 5 分制
78813.5盼之4.0螃蟹4.2

三家同法采集：同一视口、同一拦截规则、同一截图口径；扣分只体现在「能采到多深」，7881 因页面自身挂起，可验证的深度最浅。

接管方式

  • 仅连本机 127.0.0.1:9222，接管用户已打开的 7881 / 盼之 / 螃蟹 三个标签页；未新建标签页、窗口或浏览器实例。
  • 视口保持标签页原始 440×956（CSS 像素，dpr 3），未使用 Emulation.setDeviceMetricsOverride、未缩放页面、未开设备模拟。
  • 交互全部走页面内 DOM 事件（click 序列），每步间隔 0.6–1.8s 随机；未使用高频批量输入，未触发任何滑块/图形/短信验证。

请求拦截

双重拦截：CDP Fetch 域 + 页面级 fetch/XHR/beacon 守卫。规则：方法为 POST/PUT/PATCH/DELETE、URL 命中 publish|save|create|submit|goods，且不属于读接口（publish/flow/*、default/value、zone-prompt、list|query|detail|info|count|config|option）时直接 abort。本轮全程 0 次写请求穿透。

方法教训（本轮踩到并修正）：最初的规则把 OPTIONS 预检与 goods-* 读接口一并拦了，导致 7881 首页游戏卡片点了没反应、盼之区服列表为空——页面初始化依赖这些读接口。改成「只拦写接口」后复测恢复正常。这也说明：把 7881 卡片点击无响应直接判成产品缺陷是不成立的，该现象已从结论中移除，仅作为「未验证项」记录。

边界与偏差

  • 7881 未能进入填单层：营地ID 授权查询 60s 无返回，表单 12 项字段本轮未复测，报告中涉及 7881 字段的内容以入口可观测字段为限。
  • 盼之未完成 QQ 扫码授权（无登录态，按约束不注册、不绕过），售价/费率层只记录文案与位置，未取到真实费率数值。
  • 三家均为未登录/半登录态，登录后才出现的字段（如螃蟹的实名身份证、7881 的保证金提示）标注未验证。

04字段联动

本页评价 · 5 分制
78813.0盼之2.2螃蟹4.2

螃蟹的联动是「填了就反馈」，盼之的联动是「一切重来」，7881 的联动有一处伪选项（交易类型只有一项）。

7881：三段接力 + 一次伪选择

  • 运营商未选时，交易类型不可点；选「安卓QQ」后出现唯一选项「平台代发」，点选即整页跳转到营地ID 页，运营商与交易类型不再回显在营地页。
  • 营地ID 页的信息密度最高：3 步流程条（发布账号 / 下单支付 / 客服验号 / 资料换绑 / 交易完成）+ 5 条温馨提示 + 图文教程视频位，正文与提示混排。

盼之：切换账号类型 = 清空重来

  • 账号类型切到「微信」，操作系统选项立即换成「安卓微信 / 苹果微信 / 安卓微信抢先服」，同时截图方式、游戏账号、授权上号整块收起，并回到「请选择区服信息」。
  • 再切回「QQ」不会恢复之前的「安卓QQ」选择，需要重新点一遍——这是本轮最影响效率的联动行为。

螃蟹：输入即联动

  • 售价 79 → 即时红字「价格范围在 80-999999」；改成 80 → 红字消失，立刻出现「代售费（费率5%，最低50元，最高5000元）：¥50 / 预估到手价：¥30」。
  • 实名选「不可二次实名（可加购人脸包赔）」→ 行内追加「发布须知：我已知晓并同意配合 若账号出现人脸验证，平台将联系您协助解除」。
  • 「同时发布连体号」开启 → 售价下方出现「定价提醒：商品价格为包含连体游戏的总价」，开关旁写「发布后填充连体信息」。

08结论与建议

本页评价 · 5 分制
78812.6盼之3.2螃蟹4.1

本轮的差距几乎全在「失败路径」：成功路径三家都能走通，一旦卡住，7881 让人干等，盼之让人重来，只有螃蟹给了退路（草稿）和明确原因（红字）。

对 7881 的建议

  1. P0 · 给营地ID 查询加超时与失败态。建议 10s 超时，超时后遮罩改为可关闭的错误卡，给出「查询不到账号 / 无角色」的三条自助路径（教程/客服/重试），并把「取消」做成显式按钮——现在遮罩期连左上返回都点不动，等于把用户锁死在页面上。
  2. P0 · 空值与禁用态要说话。营地ID 为空时按钮置灰且无提示；建议改为可点击并提示「请填写营地ID」，同时把禁用态从 #A0CFFF+白字（1.63:1）改为深灰字或加深底色。
  3. P1 · 合并「运营商 → 交易类型」两步。交易类型只有「平台代发」一个选项，属于伪选择；建议并入运营商卡片，或在运营商圈内直接展示「平台代发」标签，把 4 次点击压到 3 次。
  4. P1 · CTA 换纯色。橙红渐变白字最低 2.22:1，长文案按钮（「获取登陆账号信息」）在小屏上辨识度差；建议统一为 #F85836 纯色并把字重提到 500，或改为深色字。
  5. P2 · 补草稿能力。刷新即丢全部已选，返回无确认；可沿用竞品的「离开前询问是否保存」，至少保住运营商与营地ID。
